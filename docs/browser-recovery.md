# Explicit browser recovery

Unknown transport outcomes must reuse the original wire body and request key. A response can be lost after a session, hint, checkpoint, edit decision or answer was committed. Changing its request identity on retry can duplicate work or debit another entitlement even though server idempotency is correct.

The browser records bounded pending actions in tab-scoped `sessionStorage`, keyed by verified owner and attempt (or creation). It freezes the semantic body, expected revision and request key before sending. A successful acknowledgment clears the record. A definitive initial rejection clears it; a transport error, timeout or5xx retains it. Once an outcome is uncertain, a later rate limit/rejection cannot prove that the original action did not commit, so the exact retry remains available. Stored records are untrusted, validated and never automatically dispatched.

Reload restores explicit recovery choices. An unresolved start restores its original scenario/configuration rather than creating another attempt for a newly selected card. Learners can exit to saved history while retaining an unresolved admission. Acknowledged older replay results cannot replace a newer polled session revision. Changed semantic inputs use separate keys; server CAS and lifecycle checks still apply. Pending review/cancel state does not silently advance a stage or commit an answer.

Storage is bounded to20 intents and160,000 characters per scope,32 scopes and500,000 characters overall; each wire body and intent is separately bounded. A storage failure blocks a new action with an actionable saved-work message. Local draft files remain distinct from acknowledged evidence. Successful account deletion/sign-out clears Lab browser recovery/draft records; successful attempt deletion clears its attempt-scoped records. Browser cleanup failures are reported rather than silently treated as successful erasure. This browser storage is not an authorization boundary, durable server backup, cross-tab synchronization or an external-provider exactly-once guarantee.

Native dialogs prevent default Escape closure and delegate to the component's explicit close/busy policy, avoiding a closed-but-mounted modal after an ambiguous start. Failed or cancelled coaching exposes safe retry using frozen evidence. The server allows pausing only in practice; simulation keeps its selected help policy and advisory timer.

`tests/e2e/recovery.spec.ts` exercises lost acknowledgments, exact retry bodies/keys, reload recovery, changed intents, failed/cancelled report states and actual local create/hint invariants without inference or runner calls. Mobile screenshots and keyboard/dialog behavior are checked separately. Live network/provider interruption and accessibility review remain deployment qualification.
