# Controlled evaluation policy binding

New development and private role recordings capture the model policy once, before writing the run journal. Each provider role receives an explicit binding containing its requested model, prompt/schema/context versions, input/output and response limits, timeout, configured prices and conservative reservation. Assistant ask/plan/edit candidates share the assistant role policy. Production adapters receive that captured binding; later ambient model, price or output-limit changes cannot replace it. Immediate inference feature and credential shutdown controls still apply.

New artifacts store the bindings in optional top-level `inferenceBindings`. Candidate provenance records the provider, role, schema/context versions and binding digest. A validated candidate must match the admitted policy and usage calculation, and its reported output model must match the exact returned provider identity. A provider may resolve a requested alias to a different snapshot; the two identities remain distinct. Rejected outputs retain known charge information or the outstanding reservation when the charge is unknown. Recording never retries or resumes paid work automatically.

Offline validation uses recorded bindings and prices, without consulting current deployment configuration. Historical artifacts without these fields remain readable under their historical contract. Partly removing a recorded binding while retaining bound inference fields is rejected. Existing benchmark, attempt, context and private-plan digest construction is unchanged; new run and candidate digests include their additional provenance, so older annotations cannot approve a changed artifact.

Bindings and provider/reviewer identities in imported artifacts remain attestations, not independently authenticated receipts or expert truth. Passing structural validation supplies no feedback-quality, holdout-custody, pilot-learning or release approval claim. The regression checks use hypothetical data and mocked HTTP only; this change makes no live provider calls and supplies no new model qualification.
